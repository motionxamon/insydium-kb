# Перекраска закэшированных частиц через nxColor (и ограничение скорости по цвету)

- Источник: Top Tip Tuesday — Color Post Cache — https://www.youtube.com/watch?v=cG7K452FWwc (2026-02-17)
- Хост / поколение: NeXus (nxFluids SPH Granular, nxWind Von Karman, nxColor, nxSpeed + Mapping, xpCache)
- Задача: использовать цвет как драйвер симуляции, закэшировать, а затем перекрасить под финальный вид без пересчёта.

## Симуляция (цвет управляет движением)
1. Частицы падают (nxGravity) и сдуваются **nxWind Von Karman** с вариацией силы.
2. **nxFluids SPH → Granular**; в раскрывающемся Substeps **выключите Adaptive** для гранул (для жидкостей adaptive оставляйте).
3. Слой Noise в **nxColor**: noise **Turbulence**, scale 200, частота пониже → анимированные чёрно-белые пятна.
4. **nxSpeed** *последним* в стеке: слой **Incremental**, Speed Value 0 (без изменений), **Max Speed clamp 70**. **Mapping**: Color → **Speed Max** этого слоя → чёрные частицы не могут двигаться (0), белые движутся свободно (70). → текучее, пятнистое движение (та же идея, что в советах про поток лавы).
5. Кэш (xpCache).

## Перекраска после кэша
6. Некоторые nx-модификаторы (включая **nxColor**) всё ещё вычисляются на закэшированных частицах. Отключите цветовой модификатор симуляции; добавьте новый nxColor:
   - Gradient (Parameter) по Speed (синий медленно → белый быстро), или
   - слой **Time Dependent** с preset палитры клиента, Time to Completion 50 F, **Reverse** → цвета циклически сменяются.
   - Слой **Blend: Screen**, чтобы совместить новую палитру с закэшированными чёрно-белыми значениями.
