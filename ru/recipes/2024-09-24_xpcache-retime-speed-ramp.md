# Плавные speed ramp в слоу-мо на закэшированных частицах (xpCache Playback Scale / Offset / Retiming Time in seconds)

- Источник: Top Tip Tuesday — Retiming Cached Particles — https://www.youtube.com/watch?v=MChyNywlLF8 (2024-09-24)
- Хост / поколение: C4D; воспроизведение **xpCache** (только частицы)
- Задача: реальное время → сильное слоу-мо на всплеске → реальное время, с интерполированными частицами без дрожания.

## Шаги
1. xpCache ▸ Playback: включите **Hold** (за пределами закэшированного диапазона держит последний кадр вместо живой симуляции).
2. Постоянная скорость: **Scale** (200 % = вдвое быстрее, 50 % = вдвое медленнее, 5 % = экстремальное слоу-мо); **Offset** (например, **25** F), чтобы дойти до интересного момента. Scale нельзя анимировать.
3. Рампы: Retiming **Time in seconds**. Ключ **0 s на F0** и **100/30 = 3.333 s на F100** (в поле работают выражения; используйте fps своего проекта).
4. Timeline ▸ F-curve временного трека кэша: поставьте оба ключа в **Linear** (дефолтный Bezier даёт Ease in/out).
5. Ctrl-клик по кривой там, где начинается слоу-мо → ключ; ещё один ключ примерно на **F50**.
6. Выделите **оба** ключа и потяните их вместе вниз (или позже вправо): участок между ними становится пологим (слоу-мо), а внешние склоны остаются на полной скорости.
7. Опционально — Bezier Ease между ключами; нисходящий склон проигрывается в обратную сторону.

## Подводные камни
- Работает только для кэшей **частиц** — ретаймленные кэши OpenVDB mesh или трейлов не будут проигрываться плавно (см. рецепт 2024-10-29 про мешинг из ретаймленных частиц).
- Не искажайте внешние склоны, иначе участки «в реальном времени» поменяют скорость.
