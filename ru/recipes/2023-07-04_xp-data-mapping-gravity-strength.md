# Основы Data Mapping: сила гравитации от радиуса, яркости цвета или пользовательского значения (вкладка Mapping в xpGravity, Extended Data User Value)

- Источник: Top Tip Tuesday — xpData Mapping — https://www.youtube.com/watch?v=QqtVVMajP5k (2023-07-04)
- Хост / поколение: C4D; G1 CPU X-Particles (xpEmitter, xpGravity Mapping)
- Задача: заставить частицы падать с разной скоростью в зависимости от их собственных данных.

## Исходная сцена
Частицы с **xpGravity**, отскакивающие от пола; radius эмиттера **20 cm**, variation **15** (→ 5–35 cm), цвет Display **Gradient Random**.

## Шаги
1. xpGravity ▸ вкладка **Mapping** ▸ Add map. Parameter = **Gravity Strength** (можно выбрать любой параметр гравитации).
2. Map To: Age → **Particle ▸ Radius**; Range Min **5**, Max **35** (из 20 ± 15).
3. Кривая: X = диапазон радиуса, Y = от 0 → до полной силы. По умолчанию большие частицы падают быстрее. Переверните (маленькие = полная сила, большие = гораздо меньше, но не ноль) → имитация сопротивления воздуха для крупных частиц.
4. Отключите эту карту; добавьте новую на **Color Brightness**: яркость 0 = без гравитации, 100% = полная → светлые частицы падают быстрее. Чуть приподнимите левый узел, чтобы тёмные тоже падали.
5. Свои данные: эмиттер ▸ **Extended Data ▸ Physical Data ▸ User Value** **50**, variation **50** (0–100 на частицу). Новая карта → Gravity Strength на **User Value**; стандартный диапазон 0–100 уже подходит → частицы с малым значением почти не двигаются.

## Подводные камни
- Range должен совпадать с реальным диапазоном данных, иначе кривая сожмётся в его часть.

## Как сейчас (новые инструменты)
У модификаторов NeXus такая же вкладка **Mapping** (Fused 2023.3+, зацикливание в 2025.4; в 2026.1 один слой мапится на несколько целей) — используйте Mapping в **nxGravity** или **nxDrag** для настоящего сопротивления воздуха (см. "nxDrag realistic air resistance", 2025-02-11).
